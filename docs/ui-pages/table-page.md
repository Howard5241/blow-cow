# Table Page

- Render condition: `App` shows the table shell when `activeRoom` exists, and `BlowCowBoard` renders this page when the in-room match state is active or finished.
- `App` provides `table-shell`; `BlowCowBoard` renders the live board inside it after the staging screen has been started by the host.
- Layout order: player ring with its centre hub, then the bottom play strip. The board hero band above them is staging-only; a live match has no header of its own.
- Players are arranged around a ring like seats at a real table. The ring is rotated so the viewing player owns the bottom angle, meaning the same physical seat appears at a different angle in each client. The viewing player's own block is then dropped out of that bottom angle and down onto the hand stage, so they sit at the near edge of the table with their hand and buttons either side of them.

## Notes

- A live match has no header band. The board hero was a full-width row of page furniture stacked above a board whose height is otherwise fixed, and it was what pushed the table past the viewport and put a scrollbar on the page. Its contents moved into the two pockets of space the hand stage already reserved and never filled: the identity half — title, room code, copy button, both status pills — into `hand-meta-row` under the hand cards, and the actions — Rules, History, Leave Room — onto the line that held only the turn heading. Everything moved is rendered smaller there, because a strip inside a panel is not a page header. Staging keeps the hero unchanged; it has no hand stage to move anything into.
- The board rotates through four dark felt gradients at round boundaries. The palette order is shuffled from the match id and then cycled, so every client sees the same colour and adjacent rounds never repeat; the transition is three typed CSS custom properties, not a timer or per-frame React update.
- `board-bs-flash` is keyed on `G.bsResolution.id`, so a new call restarts its animation and the element unmounts when the resolution clears. That needs no state and no timeout.
- There is no announcement banner. Neither procedure narrates itself in prose: the focused block, the flipped cards, and the BS verdict label carry the whole story, which is also what keeps the middle of the felt clear for the focused Seat Block to travel into. The transient fail message is rendered at board level and floats over the felt rather than sitting in the hub's column, so appearing and clearing never reflows the trump badge or the direction control.
- The Seat Status Column is the only readout that is drawn from a per-player list rather than a number, and the only one whose tooltip covers several things at once — hence one panel for the stack instead of one bubble per badge. It takes the same hub-facing placement as Seat Target Actions and Player Action Callout, which is what keeps it on screen at every seat angle without any measurement; the collision between the two is resolved by the action bubble hiding while the column is hovered, since the column is what the pointer is actually on.
- The Blind status is a display effect and lives entirely in the board. Every face-up Front Card is drawn with `unknown.png` for a blind viewer, and the `trump-card` glow is suppressed with it, since a highlight would read the trump straight through the blindfold. `faceDown` is deliberately untouched, so the flip watcher never sees a card change sides because somebody went blind. It is lifted while a BS or Reset procedure is running. Nothing secret is being trusted to the client here: a face-up table card is already public to every other seat.
- Player Action Callout sits outside its block, on the same hub-facing side as Seat Target Actions. That is what keeps a bubble on a far-right seat from running off the board and being clipped by the board's `overflow: hidden`. It is layered below the action bubble, so the buttons win if the two ever coincide.
- Callouts are per seat and never expire on a timer. A seat's line is cleared only when that player starts a turn, says something else, or a round ends — so an exchange like an accusation and its denial stays legible with both bubbles up at once, and what everyone last said is still readable while a slow turn plays out. `showPlayerCallout` writes into a `Record<seatID, …>`; two small effects keyed on `ctx.currentPlayer`/`ctx.turn` and on `G.round.roundNumber` do the clearing.
- Every callout's wording is picked from the id of whatever caused it rather than at random, so all clients agree. That matters far more now than it did with a 3.6-second bubble: a pass line can stay on screen for the rest of the round.
- Hand Stage has no header row. There is no hand title, selection count, sort label, or clear action; the selection is cleared by clicking cards or by playing them.
- A turn no longer arrives ready to play. `handleTurnStart` writes a `G.turnOpening` naming the seat on the clock, and until that seat presses `Take Turn` the server refuses every one of their turn actions. The Take Turn Cover is that gate drawn: it covers the strip whole rather than greying the buttons under it, because a turn that has not been taken is not a turn with some actions missing — it has not started. The block buttons are not covered, so `getCallBSFailure`, `getConspireFailure`, and `getManipulateFailure` each carry the long form of the same sentence.
- The cover is a sibling of Hand Stage rather than a child of it, and `take-turn-open` lifts the whole strip to `z-index: 3`. Both are needed: `hand-stage` isolates its own stacking context, and the viewing player's Seat Block is dropped into this strip from the ring above, so without the lift the block would paint through the curtain and sit over the button in the middle of it.
- The gate blocks only the actions that belong to the turn. Cheats are defined by being taken out of turn and stay open, as does `Accuse` — a table cannot be made to wait on a button nobody has pressed yet, and an untaken turn can sit there as long as its owner takes to notice it. That is the whole difference between the two halves of `G.turnOpening`; the taken half with a live reveal *is* counted by `isProcedureRunning` and does hold the table.
- Pressing `Take Turn` is what runs the Reveal Rule, and the reveal is now performed by hand rather than happening on its own. The player's own block is pulled to the centre with the same `focused-seat` transform a BS reveal uses, they click each card the turn owes to flip it, and `Continue` sends the block home and hands them the turn. There is no lead-in: nothing is drawn between the press and the travel, and no measuring sequence can be running, because the server refuses every move that could start one while the walk stands.
- Which cards the walk asks for is fixed by the server at the press and published as `turnOpening.reveal.cardIDs`, so the client lights up exactly those and no other face-down card of the seat. The Spy owes one card of a pair and the server draws which one, which is what keeps the ability random rather than quietly turning it into a choice — their `Continue` therefore appears with a card still face down, and that is why the turn reveal has its own completion test instead of reusing `canAdvanceReveal`.
- Two situations skip the walk entirely and simply write what the rule owed: a pile already fully face up, and a play The Mime's disguise is no longer drawing. A card that is not on screen is not one a client can be asked to click, and revealing it changes nothing anybody can see either way.
- Blind is deliberately *not* lifted for a turn reveal, unlike a BS or Reset one. Those lift it because a blind caller could not resolve a challenge they started; here there is nothing to resolve, so a blind player turns their own cards face up for the table and still cannot read them.
- `turn-direction-arrow` is scaled up past its container and rotates slowly in the active direction, because the glyph only fills the middle 58% x 52% of its 512px canvas. Only transparent padding overflows, and `pointer-events: none` stops that overflow from widening the button's click target.
- The seats and the Table Center Hub are both nudged down into the empty bottom slot, by `--seat-ring-shift-y` and `--hub-ring-shift-y`. Both are fractions of `--seat-block-height`, which lives on `player-ring` so the two shifts and the ellipse radii all derive from the same measure at every breakpoint.
- `turn-direction-indicator` is never disabled and always shows a pointer cursor. Clicking it simply does nothing unless the viewing player is The Cat on their own turn, or is licensed to cheat, in which case it works on anybody's turn. Its tooltip warns that the block gives a nod either way, so nobody flips the sign without knowing the table can see them do it.
- Seats are laid out on an ellipse by CSS alone. `PlayerRing` gives each Seat Block a single `--seat-angle` custom property and the transform is `translate()` only. A `rotate()` or `scale()` there would inflate `getBoundingClientRect()` and break every card-travel animation, so seat blocks must never be rotated.
- `focused-seat` is the one deliberate exception to that rule. Its `--seat-focus-x` and `--seat-focus-y` are the algebraic inverse of the ring offset plus `--hub-ring-shift-y`, so the block lands exactly on the hub with nothing measured, and `--seat-focus-scale` grows it. It is safe because no measurement can overlap the focused window: the call trail runs during the lead-in, when the focused seat is forced to null; the front-card entry animation needs a new card, which no move blocked by a live resolution can produce; the Reset sequences need `G.resetResolution`, which is mutually exclusive with `G.bsResolution`; the punishment travel is gated behind `BS_PUNISH_PROMPT_DELAY_MS`; and a turn reveal is counted by `isProcedureRunning`, so it blocks every move the other three do. That constant is derived from `SEAT_FOCUS_TRANSITION_MS` and `FRONT_CARD_FLIP_DURATION_MS` rather than fixed, so retuning the focus animation cannot let a measurement land on a block that is still moving or a card that is still flipping.
- The focused block's hover cue on `revealable` cards is shadow-only, with no `transform`, unlike `cat-actionable`. A card under the pointer when Punish is pressed still has to report its true box to the travel animation.
- Seat Reveal Actions sit below the block everywhere except the viewing player's own, where they go above it. That block alone is dropped out of the ring and into the hand stage, so there is no board left underneath it and a `Punish` on yourself would render behind the hand row — which is reachable through the Contrarian, an honest BS target, a wrong accusation, and a Gambler showdown. A focused block is excluded, because the reveal walk has already pulled it to the ring's centre where below is clear again. The callout the same block is usually still saying steps up over the buttons through `--seat-callout-lift`: the caller of a BS or a Reset is who then has to press `Punish`, so the two land on the same side, and the buttons are what the sequence is waiting on.
- The ring keeps the fixed `G.seatOrder` regardless of turn direction; `turn-direction-indicator` communicates direction instead of reordering seats. Seats advance bottom to left to top to right, so the game's clockwise direction is also clockwise on screen and the arrow sprite can be read literally.
- `PlayerRing` renders every seat, the viewing player's included. That block alone is then dropped past the bottom of the ellipse by `--viewing-seat-drop` so it lands inside the Hand Stage, which reads as the player sitting at the near edge of the table. Only that one seat moves, so the seats either side of it keep their true ring positions and nothing else is covered.
- The drop uses the `translate` property rather than `transform`, which already carries the ring position; the two compose. It stays a pure translation for the same reason the ring transform does, so `getBoundingClientRect` keeps reporting the real box and no card-travel animation needs changing. `.seat-block.viewing-seat.focused-seat` sets `translate: none`, so the viewing player's own block gives up its hand-row dock and centres like any other while it is being revealed.
- Player Ring is painted above Bottom Play Strip so the dropped block sits on the panel rather than behind it. That is safe because every card-travel layer is at `z-index` 10 or 11 and still flies over the ring.
- Hand Play Row reserves its height from `--seat-block-height` and pushes the hand scroller and action row to opposite edges, each capped at `calc(50% - var(--viewing-seat-gap) / 2)`. Equal caps mean the leftover column is always centred on the board, which is where the dropped block lands, so neither the hand nor the buttons can ever sit under it.
- Below `1040px` the hand stage stacks and there is no middle column, so the drop is switched off and the viewing player stays on the ring with everybody else. The ring is still an ellipse there, so the BS focus transform still works; only `--seat-focus-scale` is reduced, because the blocks are relatively larger against a shorter ring.
- A player who leaves keeps their Seat Block in the ring, dimmed through `left-seat` and no longer selectable. Seat angles never change mid-match, so no animation anchor ever moves.
- Five character abilities fire on leaving and move that player's point total: The Speedrunner (`-2`), The Streamer (`-2`), The Pacifist (`-1`), The Drunkard (`-3`), and The Privileged (`+1`). When one fires, a Seat Leave Effect Label appears above that block naming the ability and the change, the Points Pill flashes in the matching direction, and both the label and the new total stay for the rest of the match. Nothing appears for a player whose ability never met its condition, or who had none.
- The label reads from `G.players[id].leaveEffect`, which the server writes in the same step that applies the points. Recording the delta rather than reconstructing it later is what lets the label, the Points column, and the results tooltip all name the same number; The Speedrunner in particular is applied as `-points` rather than as an assignment to `0` for exactly that reason. `formatLeaveEffectLabel` is exported from the game module and used by both surfaces, so their wording cannot drift.
- The Seat Leave Effect Label does not point at the hub the way Player Action Callout does. It sits directly above the block at every seat angle, because it is a permanent record rather than something the player just said, and a bubble that moved with the angle would read as speech. The two can never collide: the board stops feeding callouts to a seat once its player has left, filtered at render rather than cleared, so no effect is needed. Below `720px` the label goes static and takes `order: -1` inside the block, for the same reason Seat Reveal Actions goes static there.
- The match does not jump to the results table when it ends. A small Win Screen Panel names the winner and waits for a Continue press first, so the final board stays readable — the last player out triggers their leave ability at the very moment the game ends, and its label would otherwise be buried instantly. It is shown for every ending, not only the second-to-last player leaving.
- That is also why the win screen dims nothing and repeats nothing. It carries no backdrop and no closing table status: both would work against the one job it has, which is to keep the finished board legible. Its overlay is `pointer-events: none` so only the card itself is interactive.
- Continue is local state, not a move in `G`, and each player presses their own. How long anyone wants with the final board is their own business, and a synced gate would leave everyone waiting on a player who has already closed the tab. It never needs resetting because a finished match never restarts: the only route back to staging is a new match, which remounts the board.
- Below `720px` the ring gives up on being a ring and becomes a plain grid with the viewing player last. Every ref still points at the same element and all animation geometry is measured with `getBoundingClientRect`, so the card-travel sequences keep working with no JS changes. That breakpoint also zeroes `transform`, so there is no centre for a focused block to travel to; instead `focused-seat` takes `order: -1` and spans the full grid width, with taller front cards for touch. Seat Reveal Actions goes static and sits inside the block rather than below it. `accused-cheat-seat` needs no breakpoint handling, being pure colour.
- `Call BS` and `Accuse` are not in the action row. Both buttons live on the opponent's own Seat Block, pointing at the hub, and appear as soon as that block is hovered. Clicking a block still selects it, which pins the buttons open; that is the touch path, where there is no hover. Clicking again or pressing `Escape` clears the selection.
- The bubble is mounted on every selectable block and hidden with `visibility`, not `display`, so it never affects layout and stays out of the tab order until it is revealed. It overlaps its block by 2px so the pointer never crosses a dead gap on the way to the buttons. Below `720px` it is dropped from the flow with `display: none` and only selection brings it back.
- `seat-hover-frame` is the same reveal: `block_hover_icon.png` fades and scales in around any selectable block under the pointer. The sprite carries about 8% transparent padding, so the element is stretched to 122% of the block for the drawn outline to land on the block's own edge.
- Any live opponent's block responds at any time, on or off the viewing player's turn. Being out of turn is reported by the buttons as a fail message rather than by the block going inert. Only a selection made on the viewing player's own turn re-points the BS target highlight, so browsing blocks out of turn never makes another player look like the live target.
- Hover targeting is suspended for the length of a BS resolution, a Reset, an accusation, or a turn reveal, and is never offered to spectators. Nothing is selectable then, so no hover frame or action bubble competes with the resolution sequence, and in a turn reveal nothing intercepts the clicks meant for the cards. It is *not* suspended while a turn is merely waiting to be taken: the buttons stay hoverable there and explain themselves instead.
- A BS call opens with a lead-in step before the reveal procedure. The accused's block is framed in red immediately, then `x_icon.png` marks pop in one by one along the line from the caller's avatar to theirs, and `BS_target_icon.png` stamps the accused's avatar only once the last mark has landed. The bullseye then holds for `BS_TARGET_MARK_HOLD_MS` before the accused's block is pulled to the centre — that pause is the table registering who has been challenged, and is deliberately longer than the animation needs.
- `BS_CALL_TRAIL_LEAD_IN_MS` is the trail's arrival plus that hold, derived from the mark count, the stagger, and the mark animation's own duration rather than being a fixed number, so retuning the trail cannot let the reveal procedure start over a lead-in that is still playing. The target mark's delay comes from the same arrival figure, passed down as an `animation-delay`; its keyframe fills backwards from opacity 0, so the delay alone hides it and no timer or extra state is needed. A trail that could not be measured yields a zero delay and the mark stamps immediately.
- The trail is measured once, when the resolution arrives, from the `data-seat-id` attribute each Seat Block carries. That includes the viewing player's own block, wherever it has been dropped to, so a call made by or against the viewer is drawn correctly. The marks are stored on `leadInProgress` rather than in their own state, which keeps the lead-in from adding a second set-state-in-effect call site.
- The lead-in is the only timed part of either procedure. Once it ends the caller performs the reveal by hand: the accused's block scales up and travels to the centre, the caller clicks each of its face-down cards to flip them, `Continue` appears once none are left, and pressing it returns the block to the ring and brings the next player's block in. When every card on the table is face up, the table holds for `BS_PUNISH_PROMPT_DELAY_MS` and then `Punish` appears over the seat that will take the cards. Everything after the lead-in is derived from the live resolution rather than from a local clock, so every client renders the same moment without having to agree on timings, and a client that joins or reconnects mid-procedure picks it up in the right place.
- The reveal visits one player per step: the accused (BS) or the caller (Reset) first, then around the ring against `G.round.direction`, skipping anyone with nothing face down. A step covers every face-down card in front of that player, so a player holding two hidden plays still comes to the centre only once. The order is frozen when the resolution is created, so the direction flip at the start of the next round cannot reorder a procedure that is already running.
- A Cat-rehidden card counts as face down for either reveal even though it does not count as a hidden play for BS targeting. The server uses `isCardFaceUpOnTable` for the former and `getHiddenCardsForPlay` for the latter, and the client mirrors that split with `getFaceDownOverlayCardIDs` versus `getHiddenOverlayCardIDs`. Unifying them would either let The Cat manufacture new BS targets or leave a face-down card the procedure never opens.
- `revealBSCard` and `revealResetCard` write the table play's own `revealedCardIDs`, so the flip is server state: every client sees it, the existing reveal watcher animates it for free, and `playerView` stops masking that card for everyone at the same moment. The card faces never travel inside `bsResolution` at all, and `targetVerdict` and `punishment` stay `null` on the wire until the caller has revealed enough of the table to have earned them. `G.tableStatus` is broadcast too, so its BS wording never names the verdict either.
- Every move in either procedure is caller-only and there is no timeout fallback, by design. A caller who disconnects mid-reveal resumes through the same-name rejoin route rather than the table advancing without them, so a stalled resolution is expected behaviour and not a bug. `beginBSPunishment` is a separate move from `finalizeBSResolution` for the same reason: it flips a synced `isPunishing` flag so the travel animation plays on every client while the cards are still on the table, and it replays intact if the caller reconnects while it is running.
- `trump-card` uses `countsTowardReverseRule`, the strict trump rank, so Jokers and The Confused's wild Jacks do not glow. That is the set players need to count, since the Reverse Rule triggers on four or more of them. It is also self-masking: a card the viewer may not see is rewritten to rank `Joker` before it reaches the client, so an unflipped card can never light up.
- Which block `Punish` lands on is read straight off `punishment.punishedPlayerID`, so The Contrarian's reversal needs no UI of its own: their calls simply put the button on the other block. The one thing the client says about the ability ahead of time is a clause on their own `Call BS` tooltip, because the ability is otherwise passive and the call is where it is spent. Counting the glowing trump cards no longer predicts the outcome for that seat — a Contrarian call that also trips the Reverse Rule is reversed twice and lands back on the default, which the verdict line in the log spells out afterwards.
- Both buttons are always pressable and never render disabled. An illegal attempt is caught client-side, shows a `board-fail-message` in the hub, and dispatches nothing. This exists because an `INVALID_MOVE` returned by the server is silent.
- `src/ui/bsTargeting.ts` mirrors `resolveBSTargetSelection` in `src/game/blowCowGame.ts` so those messages match what the server would accept. The server stays authoritative; the mirror only decides dispatch versus message. It deliberately mirrors nothing about The Dreamer.
- `Accuse` and `Call BS` are now entirely separate moves that answer different questions. `Call BS` asks whether a hidden play really was the claimed rank, and only on the caller's turn. `Accuse` dispatches `accuseDreamer` and is the only way The Dreamer's rule-breaking can ever be caught; a BS call no longer looks at any of it, which is also why the Reverse Rule no longer has a Dreamer exception.
- `Accuse` is legal at any time, on or off the accuser's turn, against a live Dreamer — the cheats it catches happen on other people's turns, so binding it to your own would make most of them uncatchable. What bounds it is one accusation per player per round, spent whether it lands or misses and handed back by `beginNextRound`; the narrow window each cheat stays catchable for; and the table itself, since being wrong costs the accuser every card on it.
- The five Dreamer cheats close on different clocks. A direction change and a sneaked play are properties of the turn they happened in and can be accused only during that turn. Playing more cards than declared, pushing the table past its limit, and reusing the previous round's trump are all properties of a play, and can be accused only during the turn immediately after it.
- Sneaking a play is the one Dreamer cheat that hides behind inattention rather than behind `playerView`. The cards land face down in front of them and their hand count drops to match, both in plain sight; what is missing is the announcement. `sneakPlay` writes no history event and no telemetry, so no callout fires, and because callouts never expire, whatever The Dreamer last said stays up unchanged — nothing about the table draws the eye to them. Only the archive, which `hideSecretState` empties, records who did it.
- A sneaked play is therefore derived rather than flagged: any play stamped with the live turn number that belongs to somebody other than the current player can only have been sneaked, because every legal route to the table is gated on `ctx.currentPlayer`. A `wasSneakPlay` field on the play would have to survive `hideSecretState` to be useful to the server, and would give the cheat away the moment it did. The board uses the same derivation twice, both times about the viewer's own seat: to suppress the play callout, and to grey out `Sneak Play` after one has already been used this turn.
- A sneaked play is capped at exactly one card, unlike every other Dreamer cheat, which are all uncapped. A handful of cards appearing at once is the opposite of sleight of hand, and this cheat rests entirely on the table not noticing. The server rejects any other count; the button is simply disabled, with a tooltip, when the selection is not a single card.
- A sneaked play changes nothing about the turn it interrupts. It ends nobody's turn, selects no trump, breaks no pass streak, does not become the latest non-passing play, and does not rewrite `G.tableStatus`. It also never becomes the sneaker's pending reveal, so the real play they still owe the table is not quietly retired; the sneaked cards simply stay face down until a reveal procedure or the end of the round opens them.
- A sneak is the one route to the table that does not need a trump rank, which makes its window the widest of the six cheats: it opens before the round even has a shape. `claimedRank` on the play is null until `settleUnclaimedPlays` hands it whichever rank the round settles on — through the trump-selecting play or through Manipulate — and the lie, if it is one, is counted then rather than at the sneak, because until a rank exists there is nothing to have lied about. Nothing can read that null in between: the callout is already suppressed for a sneaked play, `Call BS` needs a live trump, and a sneak is never a pending reveal.
- Taking a card back is the sneak play run backwards, and it is clicked rather than pressed: a face-up card in your own block becomes a button when you hold the licence to cheat, and clicking it puts the card back in your hand. There is no action-row control for it, which is the point — the row is where a turn is spent, and this is not a turn action. It is legal on anybody's turn including your own, and it is unlimited.
- The click target is shared with The Cat, and the take-back wins it. A Cat who may also cheat therefore palms their own face-up cards and still flips everybody else's, which is why `isCatActionable` and `isTakeBackActionable` are made mutually exclusive where the seat rows are built rather than being sorted out in the click handler: a card carrying both would wear both hover affordances. The take-back's is amber against the Cat's blue, so the two clicks read apart at a glance, and both are hover-only — a card at rest must look like every other card, or the pile itself would announce who holds a licence.
- Both affordances are computed per viewer, so a highlight here tells the table nothing: every other client computes `isTakeBackActionable` as false for that seat. The one tell anybody else gets is the card leaving the block and the hand count rising to meet it. Nothing is written to the log, nothing to telemetry, and `G.tableStatus` is deliberately left stale rather than rewritten — the next turn to begin rebuilds it — because a status line naming a smaller table would re-announce in prose what the gap is supposed to say on its own.
- Like `Sneak Play`, it is one of the few things a player may do while they are not on the clock, and it carries the same cost under a Mimic disguise: the card leaves the block at whichever chair its owner really occupies, which is the coin flip read straight off the table. That is the standing limit on the disguise rather than a new hole — an off-turn action has always been one only its real owner can press — and it is the price of palming a card while wearing somebody's face.
- The two-second lock is the one piece of this that is not about hiding. A player who palms a card on their own turn has their whole action row and every Seat Block button greyed for `TAKE_BACK_ACTION_LOCK_MS`, so the gap they just left sits there long enough to be seen instead of being closed by ending the turn in the same breath. The lock is applied over the finished `actionButtons` array rather than folded into each button's gate, so it covers every action in the row including ones added later and gives the same sentence on all of them.
- It is client-side by construction, not by omission. A deadline the server could enforce would have to be a wall clock stored in `G`, and a wall clock in `G` is not replayable — it would break the completed-match archives and the check harness both. `hideSecretState` therefore does something it does nowhere else and hands `takeBackTamper` back to a single player: stripped from every opponent, who would be checking the answer instead of gambling an accusation, and kept for its owner, who cannot use it that way and is the only client that has to serve the pause. `id` changes on every take-back, so an unlimited run of them re-arms the full two seconds each time.
- The board never checks whether a cheat is really there before dispatching, because it cannot: `G.directionTamper` is stripped by `hideSecretState` and never reaches a client. Every message `getAccuseFailure` produces is a precondition, not a hint. An accusation is meant to be a gamble about whether The Dreamer has cheated yet — not about who The Dreamer is.
- Only a seat licensed to cheat can be accused; naming anybody else shows `Only Dreamer can be accused` and dispatches nothing, and the server refuses the move outright rather than resolving it as a miss, so it costs the accuser nothing. That is safe to check client-side because characters are public: `hideSecretState` does not mask `character`, and every Seat Block already shows its own character badge. Once the No Cheating Rule is removed the check refuses nobody, because the licence stops being a character at all.
- The No Cheating Rule is the one removal that widens the game rather than narrowing it: it hands every player all six of The Dreamer's cheats and makes every seat accusable. The board mirrors that through a single `canCheat`, and every label that would have named The Dreamer switches to a plain `Cheat and …`, because at that point there is no character to credit. The Dreamer keeps their card and loses their edge, which is the same mechanic as Pass removing The Foreigner's ability, running the other way.
- A direction change writes no history event at all, whoever flipped it. Naming a cheat would make the accusation a formality; naming only the cheats would be the same giveaway in reverse, since an unattributed line could then only be The Cat's; and an anonymous line would still tell a player who looked away that *something* had happened. The move keeps a telemetry line for the completed-match archive, anonymous because telemetry is not stripped by `hideSecretState`, and the archive keeps who really did it.
- What the log does not carry, the board gives back as a movement. `G.directionFlip` is published on every flip and names the player who made it, and each client turns that into a 460ms lean of their Seat Block toward the hub. It is deliberately not a verdict: it says which hand touched the sign, never whether that hand was entitled to, so a watchful player still has to weigh the flipper's character and whose turn it was. It is the exact counterpart of `directionTamper`, which holds the answer and never leaves the server, and it is why The Cat's legal flip animates too. It is also the only word on the subject: with no log entry behind it, a player looking elsewhere has nothing to read back.
- The tell is not replayed on mount, for the same reason the punishment flash is not: a player who joins or reloads afterwards was not there to catch it, and handing it to them would turn something you had to be watching for into something you cannot miss. `handleTurnStart` clears `directionFlip` along with `directionTamper`, so the record dies with the window it belongs to. A second flip by the same player carries a fresh id and the effect clears the class across a `requestAnimationFrame` before re-setting it, or the browser would have no change to restart the keyframes from — flipping back and forth inside one turn is a legitimate thing to do.
- The lean is a translation and a border colour, nothing else. `.seat-block` documents why: `getBoundingClientRect` reports the axis-aligned box of a transformed element, so a `scale()` would inflate every measurement the card-travel animations take off that block. It rides a registered `--seat-nudge-distance` fed back into the block's own transform along `--seat-angle`, which aims it at the hub from every seat including the dropped viewing block, and it drops the `transform` transition for its duration so the transition cannot chase the keyframes and smear the nod into a drift.
- An accusation freezes every other move while it is live, the same way a BS resolution does, so it can be raised out of turn without two procedures ever overlapping. The client holds the answer back for `ACCUSATION_VERDICT_DELAY_MS` so the shout lands before the reply: a hit turns the accused's block red immediately, while a miss first puts `Nope` in the accused's callout and only then, after `ACCUSATION_DENIAL_DURATION_MS`, turns the *accuser's* block red. `Nope` belongs to a wrong accusation only — a caught Dreamer never denies it. Only the accuser ever sees `Punish` or dispatches either move, exactly as only the caller finalizes a BS resolution.
- `accuseDreamer` and `callBS` are declared `client: false`, which stops boardgame.io predicting them locally. In multiplayer the client deliberately does not re-apply `playerView` when replaying a move, so a predicted run judges the table against masked cards. For `callBS` that would briefly publish a made-up `targetWasHonest` to the caller; for `accuseDreamer` it is worse than cosmetic, because the verdict turns on `G.directionTamper`, which is stripped entirely — a predicted accusation therefore always decides "missed", and the accusation effect would capture that wrong answer into state under an id that never changes when the real one arrives. Any future move whose outcome depends on state the client cannot see needs the same flag.
- Both endings punish. A caught Dreamer takes every card on the table; so does an accuser who named someone falsely. Only `punishedPlayerID` differs, the round ends either way, and `unpunishedPlayerID` opens the next one. A caught Dreamer keeps the direction they forced — being punished is the whole consequence. The travel reuses the BS punishment animation through a single `activePunishment` descriptor, but an accusation reveals nothing first, so those cards fly face down.
- `turn.activePlayers` is set to `{ all: Stage.NULL }`, which makes every seat permanently active in boardgame.io's eyes. Without it `IsPlayerActive` falls back to `ctx.currentPlayer === playerID`, the framework silently discards every move from anybody else, and `BoardProps.isActive` goes false on their client — which would make every out-of-turn power impossible. The cost is that this game is now the sole authority on turn order: `performPlay`, `resolveDrunkardRandomPlay`, `pass`, `callBS`, `callReset` and `catHideCard` each check `ctx.currentPlayer` explicitly, and any new turn-bound move must carry its own guard. `sneakPlay` carries the inverse guard, refusing when the mover *is* on the clock. It also means a client can dispatch the `endTurn` event out of turn, which the framework used to prevent.
- There is no `En Passant` button. The Pawn's en-passant target is one of the seats the server already accepts, so the Pawn hovers that Seat Block and presses `Call BS`.
- When the viewing player is The Grandmaster and it is their turn, any seat with a hidden play can be challenged once. Spending the override is reported through the fail message on later attempts.
- When the viewing player is The Cat and it is their turn, any face-up `front-card` in any Seat Block becomes a click target that flips back face down for everyone without changing gameplay legality. The flip writes no history event and no telemetry: the card visibly turns over on every client already, so a log line would only repeat what the table just watched happen. The archive still records it.
- The Privileged do not open the round after taking the table. `wasPunishedThisRound` is set by both punishment routes, `beginNextRound` rolls it into `wasPunishedLastRound` before it picks a starting player, and `getPrivilegedStartingPlayerID` skips a Privileged carrying that flag — so the seat that won the BS call or the accusation against them keeps the start it earned, for exactly one round. The flag is public like the punishment itself, and the Seat Block reads no differently for it.
- Every action button pairs an icon with its label: `play_icon.png` for `Play`, with or without the rank selector beside it; `play_random_icon.png` for `Play Random`; `sneak_play_icon.png` for `Sneak Play`; `pass_icon.png` for `Pass`; `reset_icon.png` for `Call Reset`; `defy_icon.png` for `Defy`; `mimic_icon.png` for `Mimic`. The sprites are white glyphs, so they are filtered to black on the light enabled button and left white but dimmed on the dark disabled one. `Seek Character` and `Break Rule` are the two actions with no icon, there being no sprite for either. `conspire_icon.png` and `manipulate_icon.png` are the two that left this row with their buttons and now sit on the Seat Blocks, where the dark background takes them unfiltered.
- Every action that needs somebody to point at lives on the Seat Blocks rather than in this row: `Call BS` and `Accuse` for everyone, and `Conspire` and `Manipulate` for the one seat holding the character that has them. Both of the latter used to carry a player dropdown in the action row, and the block being clicked is what replaced it. Manipulate brought its other two selectors along, so nothing about it is decided in two places. Like `Call BS` and `Accuse` they are always mounted and always pressable, explaining a refusal through the fail message rather than going grey — which is why both grew a turn check the action-row tooltips never needed: hovering a block off your own turn is an ordinary thing to do.
- When the viewing player is The Drunkard, the action row can show a `Play Random` combo with a card-count selector and, before trump is live, the same trump selector used by the normal opening play.
- A random play is never announced. It writes no history event and no telemetry of its own, and the ordinary play event that follows reads exactly as a manual one does, so nothing on any other client separates the two — the table cannot tell whether The Drunkard chose those cards or drew them, which is the whole ability. Only the archive keeps `playMode`, and `hideSecretState` empties the archive.
- When the viewing player is The Foreigner, the `Pass` action can expose an inline selector for choosing an outside card, a Joker, or `None` before sending the pass move.
- `Defy` is the one action in this row that does not end the turn, so the row stays live and the player still owes the table a real action afterwards. Its tooltip says so, because every other button here ends the turn and nothing else on screen would suggest this one is different. It reuses the ordinary hand selection rather than opening a picker — one selected card is the whole input — and clears that selection on the way out, the same as `Play`. The card has to be a heart, which the tooltip says twice over: once when the hand holds none, and once when the selected card is the wrong suit. The rule it destroys is drawn, not chosen, which is what separates it from The Broken; both draw from the same pool of removable rules still standing, so `Defy` disappears once that pool is empty rather than becoming a free way to discard. The history line names the rule but not the card: which rule died changes the game everyone is playing, while the card came out of a hidden hand and naming it would show the table cards nobody paid to see. Only the archive keeps the card, and `hideSecretState` empties the archive.
- `Manipulate` is three decisions taken at once — the round's trump rank, its direction, and who takes the first turn — and all three are now taken on one player block: the two selectors sit in the bubble above the button that hands them the round. The selectors write one shared choice rather than one per block, so every bubble shows the same rank and direction and whichever one is open is the one that sends the move. It ends The Invisible Hand's turn without a play, so it is also the only turn-ending action that puts nothing on the table. That is why `Call BS` stays unavailable to the player it hands the turn to: `lastNonPassingPlayerID` is deliberately left null, there being nothing to challenge.
- Its window is the narrowest of any ability, and the tooltip spends most of its length on that rather than on what the button does — starting player, first turn of the round, nothing having happened yet. Unlimited use needs no spent flag, because handing the round away is exactly what stops the player being the starting player, and they may not name themselves, which the block-mounted button makes literal: their own block is the one seat that never carries it.
- The rank selector omits the previous round's trump rather than disabling it. Manipulate obeys the Rank Change Rule, so that rank is not a choice the control can offer at all, and it reappears if the rule card is removed from the match.
- The player handed the turn loses only `Pass`, which their own Pass tooltip explains and the table status announces. Nothing else needs taking: on the first turn of a round no cards have been played and none are on the table, so `Call BS` and `Call Reset` are already unavailable on their own terms. The lock covers that one turn — `handleTurnStart` lifts it as soon as any other turn begins.
- The Privileged shuts The Invisible Hand out entirely while it holds the start, since being the starting player is the timing condition. That falls out of the two abilities rather than being written anywhere, and it lapses for the one round after The Privileged takes the table.
- `Conspire` is the one action anywhere on the board that neither ends the turn nor leaves it alone: it takes the turn hostage. The moment it lands, the hand strip is showing somebody else's cards, `Pass`, `Call Reset`, `Call BS` and `Accuse` all refuse, and the only move left is a play out of the hand it opened. There is no cancel, which is the point — the peek and the obligation arrive together, so the ability can never be spent as a free look. Its own tooltip and every refusal message say so rather than leaving the player to discover it.
- The borrowed hand is the only time `hand-scroll-row` shows cards the viewer does not own, and three things say so at once: the Conspiracy Banner above it, the tinted dashed frame on the row, and the play buttons' tooltips naming whose cards are about to be spent. The selection state, the Play buttons, and the callout text are all reused unchanged — only the seat the strip reads from moves, which is `handSourceSeatID`. That same value drives the hand add/remove animation refs, so swapping into a conspiracy reads as a seat change rather than as every card being dealt and discarded at once.
- Only The Mastermind's own client sees those faces. `hideSecretState` unmasks exactly one extra hand, for exactly the seat named by `G.conspiracy.playerID`, and closes it again the moment the play clears the conspiracy. The conspiracy record itself is public, so every other client can see that a hand was opened and whose — just not what was in it.
- `Mimic` is the only ability on the board that is entirely a drawing. `G.mimicry` changes nothing about the game: The Mime keeps their own hand, their own plays, their own character and their own points, and the server reads all four exactly as it did before. What the record does is tell every client except The Mime's own to draw one block as a copy of another — avatar, name, character badge, point total, scored ranks, hand count, connection state, and the cards in front. Everything in it is a snapshot taken when the ability landed and none of it moves afterwards.
- The point of the copy is that the two blocks then read the same whichever way the coin fell, and the snapshot is what makes that true rather than a live mirror. The turn always belongs to the block in The Mime's old chair — either they kept it or they handed it over by moving out of it — so that block is the one that acts. The board subtracts The Mime's own plays from the copied hand count and stacks them onto the copied pile, so the acting block loses cards and gains a pile either way, and the other one does neither. A live mirror would leak the answer instead: a shared count that tracked the source would move on a swap and stand still without one.
- The swap is a real seat trade, in `seatOrder` and in both `seatIndex` values together, so turn order, the ring, and every `Seat N` label follow it. `seatIndex` staying equal to the position in `seatOrder` is what keeps the labels attached to chairs instead of players, and so what stops the trade renaming anything. The trade is permanent; the drawing is not.
- The drawing is worn for the rest of the round. No turn start takes it off, The Mime's own included — they keep acting from behind it, and their plays keep stacking onto the copied pile. It comes off at the end of the round, when either player leaves, and the instant a BS, Reset, or accusation procedure begins, the last because a borrowed pile would be exposed as a copy the moment the first card turned over. Since every way a round can end is one of those procedures, the procedure is always what takes it off, and `beginNextRound` clearing it again is belt and braces for a restored match. `hideSecretState` needs no clause for any of it, since nothing it copies was ever secret.
- The Reveal Rule is the one part of the disguise that needed real machinery rather than a snapshot. Both blocks draw the *same* physical cards, so obeying it literally flips the borrowed pile on both at once — at whichever chair the source really sits in, which is the coin flip read straight off the table, and on the very next lap. `mimicry.revealedPlayerIDs` splits it per chair instead: each of the two turns its copy of the pile over when the turn reaches it, so the chair after the disguise opens first and the chair holding the turn follows a lap later, whichever way the seats fell. Only the cards that were still face down when the copy was taken are held back; one already face up is public, and hiding it again would be taking something off the table.
- That means the source's own block holds its borrowed cards back too. In the swapped branch they have genuinely revealed and are still drawn face down on their own block until the turn returns to them — by which point the same cards are already face up on the other block, so nothing is withheld for longer than a lap, and the unswapped branch has the identical gap in the mirror position. The turn a swap hands over does not count as the source arriving at their chair, because from outside the ring the turn never moved; `mimicry.pendingHandoverPlayerID` carries that one skip and is the only part of the record `hideSecretState` strips, since only a swap ever sets it.
- `getDisplayedFrontCards` in `src/ui/tablePlays.ts` is the single source of truth for all of this, and the reason it is a shared function rather than inline in the seat rows: the flip watcher reads it too, so a card can never be animated as flipping while it is drawn the other way up. That watcher is now one effect over displayed face-down state rather than the two it replaced — a reveal and a Cat re-hide are the same event seen from either side, and both were previously keyed on the table rather than on what the ring draws.
- `mime disguise symmetry` in the check script is the guard on all of it. It runs both branches of the coin flip side by side through the same observable sequence of turns and compares the ring chair by chair, through `playerView` for an uninvolved seat, so it is literally what a third party would render. It compares drawn sprites rather than underlying ones, which is the line this character draws throughout: in the swapped branch the source's faces are unmasked on the wire while still being drawn face down, a difference a client could read out of its own state and never one it puts on screen.
- Three board effects had to be taught about it. The front-card entry watcher re-baselines instead of animating whenever the disguise goes on or comes off, because a block's whole pile changing in one render would otherwise be dealt in from that seat's hand pill — on one block only, which would point straight at it. `buildTurnStatus` drops to a bare table-and-chair line while a disguise stands, because the action space it normally recites is read off the acting player's own character and history and would name in prose what the two blocks are hiding. And a disguise arriving seeds The Mime's block with whatever line its source was saying, so the two do not differ over one of them being mid-sentence.
- That seed goes into `playerCallouts` rather than being drawn on top of it, so from there it behaves like any other line on that block: overwritten when The Mime speaks, dropped when their turn starts. Both are what would have happened to the source's line on that chair had the seats moved instead. It is skipped when The Mime is the one on the clock — the no-swap case — because a block whose turn has begun has already had its line cleared, and seeding then would put a line on the acting block that the other case does not have.
- It is an illusion aimed at the screen, and it is honest about being no more than that. Four things can still give it away. An ability only the copied character has is still one only its real owner can press, which is the cost of copying a face without the card behind it. The cards-on-table counter counts the real cards, so the two drawn piles can add up to more than it says. A Mime who plays more cards than the source was holding clamps the copied count at zero while cards keep landing in front of them. A source holding The Foreigner can move their real count and points on a pass, which the frozen copy does not follow. And underneath all of it, a client that reads its own state rather than its own screen can see which seat is disguised, because `G.mimicry` names it. Hands, plays, and verdicts stay hidden exactly as they were; this hides nothing that `playerView` was ever responsible for.
- The Clown is the one character with no control of its own: nothing is added to the action row, and what changes is that the row stays live after a `Play` instead of going over to the next seat. The round's first play by The Clown leaves the turn where it was, and `G.encore` is what the board reads to say so. Both play buttons go grey and both tooltips explain why — a second play is the one action the encore does not buy — while `Pass`, `Call Reset`, `Call BS`, and `Accuse` all stay exactly as they were.
- There is no decline button, because `Pass` already is one. Pressing it ends the kept turn and counts as an ordinary pass, streak included, which its tooltip says outright — the streak is the one part a player who has just played would not expect. That is also why the encore is refused outright when it would buy nothing: with the Pass Rule removed, nobody to challenge, and a table short of its cap, a kept turn would have no legal move left at all, so the play simply ends the turn as usual and the round's use goes unspent.
- `Call BS` needed the only real machinery. The play that earns the encore makes The Clown the latest non-passing player, so reading the round the usual way would answer "yourself" and quietly close the action the encore exists to hand back. `G.encore.bsTargetPlayerID` remembers who the target was a moment beforehand, and `getClientDefaultBSTargetSeatID` reads it through the same shared helper the server does rather than mirroring it, since the record is public state — it names whoever the whole table could already see was challengeable. The Seat Block tooltip switches wording to match, and warns that The Clown's own fresh cards flip with the rest of the table.
- The table status says the turn is still held rather than leaving it to be inferred, since a turn that does not move on after a play is otherwise indistinguishable from a stalled table. The action list in that line drops `Play` for the same reason the buttons do.
- The action row is otherwise entirely turn-bound, so `Sneak Play` and `Seek Character` are the two exceptions that make the row live while it is headed with somebody else's name. Showing them to The Dreamer and The Seeker alone gives nothing away, because characters are public anyway: `hideSecretState` does not mask `character`, and every Seat Block already shows its own character badge. Its tooltip explains the window; there is no fail message, because unlike `Call BS` and `Accuse` the button is genuinely disabled when the move would be refused.
- `turn-direction-indicator` becomes a hover-highlighted button that flips the current direction for The Cat on their own turn, and for The Dreamer on any player's turn. Its mirrored counterclockwise glyph keeps a positive CSS rotation because mirroring reverses the perceived spin. For The Dreamer it is a cheat, measured against the direction the *current* turn opened on: flipping back within the same turn erases the tamper along with the advantage, and once that turn ends the tamper is uncatchable.
- `front-card-row` keeps cards in their natural table order; face-up cards are not regrouped ahead of face-down cards. Cards overlap so a full row fits the block, but each card stays about half visible. Cards are never removed from the row, because their elements anchor the punishment and reset travel sequences.
- A seat with no cards in front renders no front-card markup at all. `seat-front-cards` keeps its reserved height, so every Seat Block stays the same size and the ring radii, which assume a fixed block height, do not shift.
- Character descriptions are not repeated in separate text because they already exist inside the character card sprites.
- A character card animates wherever it is shown at readable size — the enlarged overlay and the Seeker Picker — when its art ships as a numbered run starting at `1`, such as `The Prototype 1/2/3.png`. Frames hold for 300ms each and are preloaded, so the loop does not blank partway through. Everything else, including the 30px Seat Character Badge, shows the first frame as a still: a badge that size reads as a flicker rather than as motion. A single-frame character starts no timer at all.
- Rule cards are the deliberate exception to that. Their illustrations are pure art and carry no text, so the title and description are rendered as real text beside the sprite. A rule with no sprite yet falls back to a placeholder tile rather than a broken image, so the panel is readable before the art lands.
- The Rules panel and the History panel are mutually exclusive: opening either closes the other, so two `board-overlay` panels never stack on the board.
- Rule card statuses come from `G.rules`, which `hideSecretState` leaves untouched — every seat reads the same statuses, and there is nothing hidden to protect. The panel falls back to an all-active default when the field is absent, because a match staged before rule cards existed restores from `data/matches/` without it.
- The Rules panel is paged rather than scrolled, four cards at a time. A fixed page size keeps every cell the same size and the panel a stable height, which a single scroll box does not. It also carries no header copy at all, only a Close button, because the cards are the content and the vertical space is better spent on them.
- The page size is four because that is one row. `board-overlay-panel` is `max-height: 100%; overflow: auto`, so a second row of cards this size overflows the viewport and the panel grows a scrollbar. Keeping the rules on single-row pages is what stops that — raising the page size brings the scrollbar back, however many rules there are.
- The No Cheating Rule card says only that nobody may cheat, and that only a player permitted to cheat may be accused of it. It deliberately does not list the six cheats. Spelling them out on a card every seat can open would hand new players a checklist, and the characters that use them are where they are meant to be learned.
- The four Hand Action Toolbar buttons each carry their own hue through a `--toolbar-accent` rgb triple, which one shared set of rules turns into a border, a fill, a hover glow, and an open-panel state. They sit in one strip and do unrelated things, so colour separates them at a glance rather than a single gold for whichever panel is open.
- Emotes are public, non-turn-bound events. The server validates that the sender is an active seated player and that the sprite number exists, then retains only the newest 24 events; the client only animates ids it receives after mounting, so joining or reloading does not replay old reactions. Each sprite starts on its owner's avatar, moves into the outer-side slot opposite the hub-facing action and callout bubble, then returns and shrinks away through CSS with no layout reflow or UI timer.
- The panel is animated on three levels: it rises and fades as it opens, its cards deal themselves out left to right on a per-card delay, and paging replays that entrance with a horizontal slide whose direction follows the button pressed. The grid is keyed on the page index so a page turn remounts the cards and the entrance runs again. Cards lift and their art zooms slightly on hover; a removed card's art partly recovers its colour on hover so you can still see what was taken away. All of it is registered in the `prefers-reduced-motion` block.
- Rule illustrations are cropped from the top edge (`object-position: center top`), not the centre, because the art puts its subject in the upper half.
- A `removed` card is enforced: each removable rule has a matching branch at its enforcement site in `src/game/blowCowGame.ts`, all reached through `isRuleRemoved`. An `upgraded` card is not — the `+` title and upgraded description are shown, but the rule still plays as written in `RULES.md`. The lobby's House Rules overlay is where that distinction is stated, since this panel carries no header copy.
- The deck itself is `src/ui/RuleCardDeck.tsx`, shared by three surfaces: this read-only panel, the lobby's House Rules editor, and The Broken's picker. Each passes a different `renderCardFooter`, which is what lets one set of cards carry no controls, status buttons, or a Select button.
- Avatars come from `avatar_sprites/` and are picked from a seeded shuffle of `matchID` plus `playerID`, so they are unique within a match and identical in every client without entering game state.
- `front-card-entry-layer` briefly animates new front cards from the owning seat's Hand Count Value into its Front Card Row.
- Reset runs the same caller-driven reveal as BS before its own animation chain: after a short pause, each player with face-down cards is pulled to the centre in turn, the caller flips their cards and presses `Continue`, and only once every card is face up does the table gather into a pile at the Table Center Hub, flip and shuffle face down, and deal back out across the active seats. There is no Punish step; the gather follows the last `Continue` directly.
- A Gambler Reset showdown replaces that whole chain. `G.resetResolution.showdown` is non-null while The Gambler is seated, and the gather-shuffle-deal effect bails out on it immediately, because those animations belong to a redistribution that is not going to happen. Instead every block gets its Seat Showdown Label, and after `BS_PUNISH_PROMPT_DELAY_MS` the caller gets a Punish button on the weakest seat. Pressing it arms the ordinary BS punishment travel through the shared `activePunishment` descriptor, so the cards fly to one seat exactly as a lost BS call sends them.
- The showdown's standings are withheld by `hideSecretState` until the reveal is complete, the same way a BS `punishment` is, and for the same reason: they rank cards that are still face down when the Reset is called. That a Reset *is* a showdown is public from the start, because The Gambler's seat badge is public; only the reading of each hand waits. `callReset` is therefore a server-only move like `callBS`, since an optimistic local run would rank masked hands and publish a made-up loser.
- A tie puts a Punish button on every tied block at once and the caller picks, which is the one point where the outcome is a decision rather than a reading. `beginResetPunishment` carries the chosen seat and the server re-checks it against `weakestPlayerIDs`, so a stale button cannot hand the table to a seat that was never in the running.
- The all-pass return (`kind: 'roundReturn'`) uses the identical reveal, driven by whoever passed last, and then sends each card back to the player who played it instead of redistributing.
- The Reset reveal order starts at the caller rather than at an accused, and otherwise matches BS: around the ring against `G.round.direction`, skipping anyone with nothing face down. A caller holding no face-down cards is filtered out of their own walk, so a Reset can begin on someone else entirely.
- Punishment cards always animate toward `data-punishment-target-name` on the Seat Block name.
- The seat callout is driven by the latest qualifying player action and fades out automatically after a short moment.
- `endgame-chart-panel` is populated from authoritative game telemetry stored in `G.telemetry.events`, not from ad hoc client-side reconstruction.
- `board-error-toast`, `punishment-move-layer`, `board-overlay` (the History, Rules, and Break Rule panels), `character-card-overlay`, `seeker-picker-overlay`, `win-screen-overlay`, and `endgame-overlay` are board-level overlays. `Escape` closes the topmost one, then falls through to clearing the seat selection.
- The Seeker trades their card in for any other one still going spare, and the picker opens by itself at the start of the match. Choosing overwrites `character` outright, which is also what spends the ability: the server's whole permission check is `character === 'The Seeker'`, so it closes the moment the move lands and there is no separate used-flag anywhere.
- Nothing about that choice freezes the table. `seekCharacter` is not turn-bound, so it can be made while anybody is acting, and no other client renders any part of the picker or waits on it. The picker's open state and the highlighted card are local React state for the same reason. It is still refused while a BS resolution, a Reset, or an accusation is running, like every other move, so a character cannot change underneath a procedure that has already been decided.
- There is no deadline on the choice. One that expired would take the ability away from an unlucky player rather than from a slow one. The cost is that a Seeker can hold the card and pick reactively, which is a real strategic upgrade over choosing blind.
- The picker offers `getSeekerCharacterChoices`: the room's own `characterPool`, minus every character already sitting at the table, minus The Seeker itself. Scoping it to the room pool rather than to every implemented character keeps the host's staging settings meaningful and inherits the rule keeping The Confused out of a Jack-less deck for free. A player who has already left still holds their card, so their character stays claimed.
- Seeker Picker Option shows the card sprite and nothing else, and the footer names the choice rather than describing it. The sprite is the character sheet — it already carries the ability text, which is why this panel is wide and the cards are large instead of being a list of names with descriptions beside them.
- The enlarged character card never scrolls. Character sprites are tall portraits, so on a short viewport the panel had nowhere to put the art and grew a scrollbar down its side. The kicker is gone, the heading, subtitle, and Close button are all sized down, and the art is capped by height rather than only by width, so it is the card that shrinks when the panel runs out of room. The panel uses `overflow: clip` with a clip margin rather than `hidden`, so the tilted card's near corner and its drop shadow can leave the box without a scrollbar coming back to reach them. The Seeker's picker is excluded from all of this: it reuses the same shell but scrolls its own card grid.
- The tilt frame carries the sprite's aspect ratio itself — character cards are a uniform 816x1110, or `136 / 185` — rather than letting the image size it. The glare and the foil are painted on the frame, so a frame wider than the picture lights up empty panel beside the card. It also has to be the frame that the height cap lands on: an image sized inside a flex frame takes its width from `max-width` and never gives it back when `max-height` clamps the height, which left the box at its full width while the picture shrank inside it. With `aspect-ratio` on the frame the cap transfers back through the ratio and both axes shrink together. A sprite that ever ships at a different ratio letterboxes rather than stretching, and that ratio is what would need updating.
- That card tilts toward the pointer, with a specular glare that follows it and a hard-edged foil band whose angle tracks the tilt, so the colours slide across the face as it turns. The handler writes four custom properties straight onto the node — pointer position, both tilt axes, and a lift factor — and never touches React state: it fires on every pointer move, and re-rendering a board this size at that rate would stutter. `prefers-reduced-motion` pins the tilt flat and keeps the lighting, which is not motion once nothing moves.
- A taken card is public the instant it lands, like every character: the seat's badge simply changes. `seekerPickedCharacter` is the only surviving trace that the seat started as The Seeker, since `character` has been overwritten by then, and it surfaces as a `Taken with The Seeker` line in that seat's Character Card Overlay.
- The Broken's picker follows The Seeker's shape exactly: opens by itself, dismissible, not turn-bound, refused while a resolution is running, and with no deadline. What differs is the spent flag. Breaking a rule leaves `character` alone, so `brokenRemovedRuleID` is what closes the picker and what `canBreakRule` reads.
- The Broken's effect is public and immediate, unlike The Seeker's private-until-taken choice. `G.rules` changes for everyone the moment the move lands, so a rule can vanish mid-turn. Every enforcement site reads `G.rules` when it runs rather than caching a decision, which is what makes that safe.
- The picker offers `getBreakableRuleIDs`: every rule that defines a removed variant and is still active. A rule the host already removed in the lobby is not a second target. Rules with no removed variant still render, dimmed, with a disabled `Cannot Be Removed` button — knowing what is safe is information worth showing.
- `table-shell` keeps its fixed ambient rim and noise layer while `table-board` morphs through its four round palettes.
- When the viewing player is punished, the red flash is shown on `hand-stage`.
- The room code lives behind the info icon beside `Live match`, and the adjacent button copies it.
- Only one primary manual-play button is shown at a time, and both read `Play`: before trump is live it comes with the rank selector beside it, afterward it stands alone. The selector is what says a rank is being chosen, so the label does not repeat it. The Drunkard may also see `Play Random` as a separate action.
- Action buttons size to their labels. `action-button-item` is `flex: 0 1 auto`, and the button inside a combo is `flex: 0 0 auto`, so neither grows into space it has no text for — a row of two used to become two very wide buttons of mostly empty amber, and every combo took a line to itself however little was on it. The row is right-aligned, so buttons pack against the edge and wrap only when they genuinely run out of room. Below 720px the combo items go back to a full row, because they stack into columns there and the `width: 100%` rules under each combo need a row to be 100% of.
- Table status, who is acting, scored ranks, and table capacity are exposed through tooltips in the hub, not separate rows or banners.
